# Расписание как приложение для телефона

Два способа. Первый работает сразу, второй даёт настоящий `.apk`.

## 1. Установка из браузера (PWA)

Откройте сайт в Chrome на телефоне → меню ⋮ → **Установить приложение** (или кнопка **Установить на телефон** в настройках сайта). Появится иконка на главном экране. Приложение открывается без адресной строки и работает без интернета: последнее расписание и последние загруженные замены хранятся на телефоне.

Нужен адрес с `https://`. Если сайт выложен на GitHub Pages или Vercel, это уже так.

## 2. Настоящий APK (Android-приложение)

Сборка идёт в GitHub Actions, ставить Android SDK не нужно.

1. Загрузите проект в репозиторий (файлы из этого архива поверх старых).
2. В репозитории: **Settings → Secrets and variables → Actions → Variables → New repository variable**.
   Имя `API_BASE_URL`, значение — адрес, где работает API замен, например `https://ваш-проект.vercel.app` (без слэша на конце, обязательно `https://`).
   Без неё расписание в приложении будет, а замены и уведомления нет.
3. Вкладка **Actions → Build Android APK → Run workflow**.
4. Когда сборка зелёная, откройте её и скачайте файл `raspisanie-apk` (внутри `app-debug.apk`).
5. Перенесите файл на телефон и установите. Android попросит разрешить установку из неизвестных источников, это нормально для приложений вне Google Play.

Правки сайта (`index.html`, расписание, замены) доходят до приложения сами: оно открывает сайт с Vercel (`server.url` в `app/capacitor.config.json`). Новый `.apk` нужен только при смене самого приложения (иконка, плагины, `capacitor.config.json`).

## Обновления приложения

Сборка публикуется как GitHub Release (`v101`, `v102`, …). При запуске приложение смотрит последний релиз и, если он новее установленного, показывает окно «Доступно обновление» с кнопкой «Скачать». Файл `app-update.js` на сайте и в PWA ничего не делает.

**Один раз настроить подпись** (без неё Android не обновит приложение поверх старого):

1. Создать ключ (нужен `keytool` из JDK):
   ```
   keytool -genkeypair -keystore debug.keystore -storepass android -keypass android \
     -alias androiddebugkey -keyalg RSA -keysize 2048 -validity 36500 \
     -dname "CN=Android Debug,O=Android,C=US"
   ```
2. Закодировать: `base64 -w0 debug.keystore`.
3. В репозитории: **Settings → Secrets and variables → Actions → Secrets → New repository secret**, имя `DEBUG_KEYSTORE_B64`, значение — вывод команды.
4. Файл `debug.keystore` сохранить в надёжном месте и не публиковать. Потеряете его — обновления поверх старой версии станут невозможны.

**Выпуск обновления:** Actions → Build Android APK → Run workflow, в поле «Что нового» можно написать текст для окна обновления. Телефон предложит скачать файл при следующем запуске приложения (проверка не чаще раза в 6 часов). После скачивания откройте файл из уведомления и подтвердите установку.

Первую сборку с постоянным ключом придётся поставить вручную, предварительно удалив старое приложение: оно подписано другим случайным ключом.

## Что где лежит

- `index.html`, `manifest.webmanifest`, `sw.js`, `icons/` — сайт и его PWA-часть.
- `app-config.js` — адрес API (на сайте пустой, в приложении подставляется при сборке).
- `app/` — проект Android-обёртки (Capacitor). `app/prepare.js` копирует файлы сайта в `app/www`.
- `.github/workflows/build-apk.yml` — сборка APK.
- `api/*.js` — к чтению замен и уведомлений добавлен CORS, чтобы их мог запрашивать апп. Запись по-прежнему только с паролем.
